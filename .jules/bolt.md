## 2024-05-24 - Prisma Promise.all in Transactions
**Learning:** Using `Promise.all` to parallelize queries inside a `prisma.$transaction` is an anti-pattern. Prisma interactive transactions are bound to a single database connection and execute queries sequentially regardless. Furthermore, if one query fails, `Promise.all` rejects and the transaction aborts, but the other pending queries in the array will still attempt to execute on the closed transaction, causing unhandled promise rejections and potential application crashes. The original `for...of` loop with sequential `await` was the correct and officially recommended way.
**Action:** Never use `Promise.all` inside a Prisma interactive transaction. Stick to sequential `await` within loops when inside `prisma.$transaction`.
