## 2024-05-19 - O(N^2) Product Grid Rendering Bottleneck
**Learning:** Found a severe performance bottleneck where `ProductCard` components inside the `Home` product grid were performing an O(N) array `.find()` on `cartItems` to determine each product's cart quantity. Since this is a wholesale app with potentially long product lists, rendering M products with N cart items resulted in O(N*M) complexity, causing noticeable lag and blocking the main thread. Additionally, two unused `useEffect` hooks in `CartContext` were iterating over the entire cart on every update just to calculate block-scoped variables that were immediately garbage-collected.
**Action:** Instead of repeating `.find()` lookups across components, always pre-compute an O(1) dictionary (`cartItemsMap`) via `useMemo` in context providers for frequently accessed relational data. Ensure that helper functions (like `getCartItemQuantity`) also consume the map to avoid residual O(N) paths. Finally, scan context providers for "zombie" `useEffects` that calculate unused state, as these steal CPU cycles during critical state updates.
